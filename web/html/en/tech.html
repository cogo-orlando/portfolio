Security in detail

🛡Cloudflare

✓SSL Full Strict — Google Trust Services certificate
✓Always Use HTTPS — automatic redirect
✓WAF rate limiting — /admin protected, 5 req/10s
✓Automatic DDoS protection — layers 3/4/7
✓HSTS — HTTPS enforced by the browser
✓Bot Fight Mode — automated traffic filtered
securityheaders.com rating:{{template "score-headers"}}

⚙Go backend

✓Strict Content-Security-Policy — no inline script can run, no eval, no framing
✓Spoof-proof client IP — CF-Connecting-IP trusted only when the request really comes from Cloudflare (attack reproduced in tests)
✓Honeypot — {{template "honeypot-routes"}} trap routes, 24h in-memory IP blacklist
✓Global rate limiting — {{template "rate-limit"}} req/min/IP with automatic cleanup
✓Panic recovery — stack trace logged, clean 500, message never sent to the visitor (tested)
✓Request ID — 16 hex chars, present in every log line (middleware order covered by a test)
✓MaxBytesReader 10KB — protection against oversized payloads
✓Static directory listing blocked — no reconnaissance through /css/ or /js/
✓ReadHeaderTimeout — Slowloris protection
✓Hardened healthcheck — port validated, SSRF alert (G704) fixed at the source
✓security.txt (RFC 9116) — how to report a vulnerability
✓gosec scan — {{template "nb-gosec"}} issues across the codebase

Docker

✓Multi-stage build — Go SDK absent from the final image
✓Scratch image — no OS, no shell, minimal attack surface
✓USER 1001 — non-root process in production
✓no-new-privileges · cap_drop ALL · read-only filesystem
✓HEALTHCHECK built into the binary (scratch has no shell or wget)
✓go.sum verified at build time (go mod verify) — dependency integrity
✓Static binary — CGO_ENABLED=0, no libc
✓-ldflags="-s -w" — debug symbols stripped
✓Final image ~{{template "docker-portfolio"}} vs ~350MB for a standard Alpine image

What I learned

01

Go server architecture

Building an HTTP server from scratch without a framework forced me to truly understand how the web works — routing, middleware chain, template cache, graceful shutdown. No magic: every line has a reason to exist.

02

Docker containerization

Multi-stage builds taught me that image size is not inevitable — going from 350MB to {{template "docker-portfolio"}} by separating compilation from runtime. And that a process should never run as root, even locally.

03

Hands-on web security

Implementing a honeypot, rate limiting, panic recovery, PostgreSQL RLS and a strict CSP showed me that security is built layer by layer — not an on/off switch.

04

Cloudflare & reverse proxies

Understanding what Cloudflare really does — WAF, DDoS, SSL termination, caching — gave me a clear picture of what happens between a browser and a server. It also taught me not to blindly trust headers: an IP header is only reliable if you know who set it.

05

CI/CD & automated tests

Writing {{template "nb-tests"}} tests and running them on every push convinced me that tests are not a burden — they are what lets you change code without fear of breaking everything.

06

Database security

PostgreSQL RLS, dedicated users with minimal rights, sslmode=require, REVOKE ALL — securing a database is much more than a strong password. Least privilege applies everywhere.

07

Managing vulnerabilities

When I added govulncheck, my CI discovered that production was running on a Go version that was no longer maintained, with dozens of known flaws. Deployment was blocked until I upgraded. Lesson learned: code that is safe today will not be tomorrow — it needs tooling to stay safe (regular scans, Dependabot, mandatory CI).

08

Privacy by design

Logging every visitor “just in case” means storing personal data for no reason. I anonymized visitor IPs, limited retention to 30 days and kept full IPs only for attacks. Security and GDPR point in the same direction.
