Six key protections

Spoof-proof IP

The IP sent by Cloudflare is trusted only when the request really comes from Cloudflare. The attack is reproduced in tests.

Strict CSP

No inline script can run: an XSS injection would have no effect.

Honeypot

Trap routes (/.env, /wp-admin…) block scanners for 24 hours, and they cannot tell them apart from a real 404.

Hardened container

No OS or shell in the image, non-root user, read-only files, no privileges.

Tracked vulnerabilities

govulncheck and gosec on every push and every week, updates proposed by Dependabot.

Privacy

Visitor IPs anonymized, 30-day retention, no cookies.

04 //

What I learned

01

Reproduce before fixing

For the IP spoofing flaw, I first wrote tests that simulate the attack, then fixed the code until they passed.

02

Safe code does not stay safe

When I added govulncheck, my CI found production running on an unmaintained Go version. Deployment was blocked until I upgraded.

03

Audit your own setup

Testing my own site, I found a CSP overwritten by Cloudflare and a domain without DMARC. A protection only exists if you check that it applies.
